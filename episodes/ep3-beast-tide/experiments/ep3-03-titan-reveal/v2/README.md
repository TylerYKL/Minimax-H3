# 巨兽登场 V2｜正向动作提示词版

本版TXT、全局提示词、各组提示词均采用正向动作描述，负向提示词字段留空。用户的正向写法偏好用于后续新增提示词。

依据用户上传的EP3_titan_ALL-3-shots_00001_.mp4：864×480、24fps、270帧、11.250秒。本包保留原六张首尾图、模型与采样参数，只修改动作提示词和界面秒数；不是已经验证成功的新视频。

## 成片观察与对应修改

| 原片位置（约） | 问题 | V2修改 |
|---|---|---|
| 0–2.3秒 | 巨足悬停偏久，尘土出现但承重接地不够清楚 | 先下落触地，再压实，最后尘土散开；取消落脚前等待，明确脚底不能留空隙 |
| 2.3–5.4秒 | 全身段姿态变化较少，接近静态展示 | 加入一次重量下沉、低头锁定、指爪收拢、尾端短惯性移动；不靠变焦冒充动作 |
| 5.4–11.25秒 | 起飞过长，喷流显眼、身体位移和姿态变化较弱，接近尾帧后持续时间长 | 开场即离地，较早越过桥面并到胸口侧面；后半段改为短弧线侧移与制动，缩短尾焰，不原地等到尾帧 |

巨兽与人的大小差总体已建立，但这不是精确的三维尺度验证。起飞的英雄投影随景深变小应来自移动，不应直接变形缩小。

## 修正我之前的时长写法

旧模板把输出帧数除以24写进 `shots[].durationSec`。当前已检查的Director前端会把新shot秒数四舍五入到一位小数，再按17k+5对齐：

- 124/24=5.1667 → 5.2秒 → round(5.2×24)=125 → 对齐141帧。
- 因此56+73+141=270帧，与本次视频总长吻合。不能仅凭视频证明用户本机每项设置，但这条可复现的模板问题足以解释多出的17帧。
- V2填入的是**界面请求秒数2、3、5**，分别对齐到56、73、124帧；总253帧=10.542秒。UI请求秒数和实际播放时长是不同字段含义。

相关本地检查代码：Director `web/js/minimax_fl2v.js` 的 newFl2vShot/shotFrameCount，以及 `web/js/minimax_gen_timeline.js` 的 roundDurationSec/durationToMiniMaxFrames/preferredDurationSecFromFrames。已用相同数学规则检查V2输出帧数。

## 使用

1. 打开 **ALL-3-shots-workflow.json**，确认三组秒数为 **2 / 3 / 5**，对应 **56 / 73 / 124帧**。
2. 上传同编号的start/end图片到各组首尾槽。图与V1相同，可复用本机已上传图，但必须确认实际槽位。
3. 仍用FL2VA、25步、CFG1、res_multistep/simple、shift12/3、seed888、864×480、24fps。Turbo/Combat旁路，段间引导关闭，静音；其他设置不变，方便比较。
4. 优先单独重跑 **01-foot** 和 **03-launch**；02仍提供新版，但不是落脚/起飞问题的主因。每组独立TXT和JSON均在包内。
5. 先核对输出长度和动作。总片正好253帧才可运行conform_10s.py校准十秒；否则保留原片核对分组长度。

## 提示词解决不了的部分

巨足尾帧的足底被凸起碎路面和烟尘遮挡，接地关系不够明确；即使文字强调，模型仍可能生成悬空脚。V2保留图片做对照，如果仍未压实，应重做脚底完全接地、无透光空隙的尾图，不继续叠加提示词。

起飞首尾跨度大且人物小，FL2V只约束端点，不保证速度曲线或路径。因此V2仍需实测。不要把“约1秒/2秒到达”理解成模型的硬时间控制。本次没有重新生成首尾图，也未运行H3。
