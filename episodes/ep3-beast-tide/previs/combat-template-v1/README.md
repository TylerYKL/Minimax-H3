# EP3 可复用战斗预演模板 v1

先把一个完整动作段落做成统一时间线，再扩展整集。本版是约 **3.92 秒、两镜头**的“背后突袭 → 察觉 → 转身开盾 → 撞盾击飞 → 俯视撞楼 → 局部坍塌”。不是完整 75 秒 EP3，也不是 H3 成片。

## 先看完整预览

- **[combat-master.mp4](exports/combat-master.mp4)**：完整灰模剪辑，94 帧／24 fps，无声。
- [关键帧](exports/keyframes.jpg)：对应完整预览的帧号。
- [自动导出的镜头素材、提示词、工作流](exports/)：先审整段动作，再决定是否运行 H3。

与之前不同，这两个镜头共享同一个场景和同一条动作时间线。第一个镜头的击飞接到第二个镜头同一时刻的位置，没有把两个独立动作重新对齐。察觉寒意暂时采用侧面镜头内的背部冷光提示，不插入极短背部特写；原先背后特写的创意并未删除，可在后续剪辑中另行处理。

## 本版已经实现什么

| 组件 | 文件／模块 | 作用 |
|---|---|---|
| 共用场景 | `scene.py` | 统一 Aegis 1.88 米、巨兽 30 米、塔楼 40 米及道路坐标 |
| 时间线与轨迹 | `timeline.json` | 定义入爪、寒意、转身、盾、接触、撞墙时点；逐帧飞行位置和楼层下沉上限 |
| 察觉／转身／盾 | `hover_turn_guard()` | 同一角色从背向转为防御姿态 |
| 巨爪攻击 | `claw_strike()` | 入画路径、接触、冲击帧和随动 |
| 强制击飞 | `forced_flight()` | 明确的快速位移与关闭喷射，不依赖文字猜速度 |
| 建筑破坏 | `facade_impact_collapse()` | 撞墙闪光、破口、碎块轨迹、局部楼层下沉与粉尘 |
| 自动打包 | `export.py` | 编码源视频和总预览，生成各镜头六字段提示词与 RV2V 模板、检查帧数 |

这些模块目前驱动的是简易几何体与整体变换，**尚未接入真正的绑定骨架、动作捕捉或动作库**。挥刀与复杂近身招式也未在本版实现。它先验证我们最缺的整段编排和复用能力；今后接入骨骼模型时仍要制作或重定向身体动作。

## 总时间线

帧号从零开始。两镜头在同一世界帧 38 处切换，向右击飞方向保持一致。

| 总帧号 | 时间 | 动作 |
|---|---|---|
| 0–27 | 0–1.167 秒 | 背向悬停，盾未激活，保留简短建立画面 |
| 28 | 1.167 秒 | 巨爪突然进入身后 |
| 29–30 | 1.208–1.292 秒 | 背部冷光掠过，表达察觉寒意 |
| 32–35 | 1.333–1.500 秒 | 四帧转身；34 帧开始开盾，35 帧完整 |
| 36 | 1.500 秒 | 撞盾，冲击峰值，喷射关闭 |
| 37 | 1.542 秒 | 已与巨爪分离 |
| 38 | 1.583 秒 | 切俯视，沿同一位移轨迹继续飞行 |
| 41 | 1.708 秒 | 撞入外墙；即第二镜本地第 3 帧、0.125 秒 |
| 42–93 | 1.750–3.917 秒 | 破口、碎石、粉尘与局部楼层下沉 |

建筑坍塌为程序化运动示意，不是结构工程仿真。没有用整段变速来伪造快速击飞；速度由逐帧位移直接确定。

## 修改一次，自动更新全部输出

在仓库内保留本目录和已有实验模板。修改 `timeline.json` 后运行：

```sh
blender -b -t 4 --python render.py -- --output /path/to/frames
python export.py --frames /path/to/frames
```

需要 Blender 4.3.2 或兼容版本、Python 3、ffmpeg/ffprobe；无需让语言模型逐帧参与。`export.py` 复用仓库里的 `../../experiments/06A-rv2v-impact-separation/workflow-rv2v-template.json`，因此不要只下载两个脚本到空目录。

- 改事件时间：`events`；数值是世界帧号。
- 改击飞速度：`motion.flight_x`。数组从撞盾帧延伸到撞墙帧，元素数量须匹配这段帧数；最后一个位置应进入目标墙面。
- 改坍塌幅度：`motion.max_floor_drop`。
- 改切镜：`shots` 中的 `world_start`、`edit_in`、`edit_out`，保持世界时间连续。
- 增加新的动作类型、换骨架或改变建筑位置需要改场景／动作代码，不能仅靠现有配置完成。

改时点后提示词的事件时间也由导出脚本自动更新，减少视频与文字时间不一致的问题。构图、穿模和动作可读性仍需查看新预览，不能只依靠参数校验。

| 镜头 | 源视频 | 提示词 | 工作流 | 灰模总剪辑使用范围 |

每个源视频 56 帧／24 fps，保持现有测试规格。先在 ComfyUI 打开对应 JSON，再上传**该镜头源视频到 RV2V 源视频时间轴**。总预览只用于审片，不上传它代替单镜源视频；模板留空源视频上传路径，不伪造已上传素材。

四个参考槽沿用已测试的配置：1=Aegis 三视图；2=举盾图；3=A-team 城市外观；4=巨兽三视图。两张三视图沿用用户本机文件。[举盾图](../../references/states/aegis-airborne-shield.png)和[城市图](../../references/A-team.png)在仓库中。不要叠加旧 EP3 五角色 Shared Params 文本。

参数继续为 Ref2VA、Turbo 1.0、4 steps、CFG 1、euler/simple、shift video/audio 12/3、seed 888、864×480、24 fps。Combat 旁路、段间引导关闭。静音导出时 CreateVideo 的 audio 输入不连接，Director 的 audio_vae 保留。

这里只自动准备素材与独立工作流，**没有连接用户 ComfyUI、没有自动排队提交，也没有执行 H3 生成**。完整提示词和源视频均未在 H3 验证。尤其第一镜把转身和盾击重新连在一起，不能因为单项实验通过就保证组合一次成功。

H3 可能提前命中或延长动作。上表的切点只对灰模准确；H3 输出应按实际“命中→分离→撞楼”重新定剪，不能盲目按同一帧号截取。

## 下一步如何扩展

先集中审这一个连续段落：角色方向、尺寸、何时转身、盾击时点、俯视切点、撞楼速度和坍塌幅度。修改确认后，再扩展挥刀／闪避／追击等动作模块，并编排更多剧情段落。正式 EP3 剧情文件和原实验均未替换。
